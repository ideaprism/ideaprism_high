# 🤖 챗봇 구조 및 이식 계획 분석 (By 지노 수석)

## 1. 현재 구조 분석 (2026-02-12 기준)

프로젝트 내에 두 개의 챗봇 관련 구현체가 혼재되어 있음을 확인했습니다.

### A. 메인 서비스 챗봇 (Active)
- **소스 위치:** `src/components/chat/ChatWindow.tsx`
- **엔드포인트:** `/api/chat` (Next.js 로컬 라우트) -> Supabase Edge Function (`/functions/v1/chat`) 호출
- **특징:** 
    - 현재 실제 서비스 중인 UI.
    - `src/app/layout.tsx`에서 전역 호출됨.
    - Dify 스타일의 심플한 카드 UI 및 RAG 출처 표시 기능 포함.

### B. 중복/테스트 챗봇 (Stray)
- **소스 위치:** `src/app/test/tag_chatbot/`
- **특징:**
    - 외부 프로젝트를 통째로 복사한 형태의 독립 구조.
    - 내부 `src` 폴더가 비어 있거나 불완전함.
    - 전용 `.env.local` 파일을 별도로 보유하고 있어 로직 혼선 유발 가능성 있음.

### C. 챗봇 시각적 어드민 (Visual Admin)
- **소스 위치:** `src/app/test/admin/page.tsx`
- **역할:** `@xyflow/react`를 이용해 챗봇의 지식 트리/워크플로우를 시각화하고 DB(`bot_settings`)에 저장하는 도구.

---

## 2. 향후 작업 방향 (대표님 지시사항)

1. **독립 개발 원칙:** 챗봇 기능은 본 프로젝트와 결합도가 높으므로, 별도의 독립 폴더(또는 환경)에서 완벽히 고도화한 후 본 프로젝트로 이식하는 방식을 취함.
2. **이식 대상:** 
    - 챗봇 자체의 인터랙션 로직.
    - TAG 엔진 기반의 워크플로우 연동.
    - 통계 데이터(건수, 퍼센트) 및 검색 최적화(키워드 추출) 로직.
3. **정리 대상:** `src/app/test/tag_chatbot/` 등 불필요한 잔재 코드는 이식 완료 후 정리하여 아키텍처 결벽 유지.

---

## 3. 기술적 특이사항
- **Edge Function (v4.x):** 현재 히스토리 관리, 테이블 인지, 직접 응답(Direct Response) 기능이 구현되어 있으며, 통계 언급 및 가이드 제공 로직 강화가 필요함.
- **TAG Engine 연동:** `tag_summary_prompt` 및 `router_mini_knowledge` 등의 노드 아이디 매핑이 현재 어드민 UI와 Edge Function 간에 정확히 일치해야 함.
